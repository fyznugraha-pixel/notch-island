# Laporan Tugas T01: Backend & IPC

## 1. Lingkup yang Diperiksa dan Tidak Sempat Diperiksa

### Lingkup yang Diperiksa
1. `src-tauri/src/lib.rs` (baris 1-6627): seluruh `#[tauri::command]`, manajemen state (`Mutex`, `OnceLock`, `LazyLock`, `Atomic*`), helper dekode gambar/clipboard/OCR, HTTP proxy (`fetch_external_lyrics_api`, `ai_http_request`, `ai_http_stream`, `cancel_ai_http_stream`), penangkapan jendela (`capture_hwnd_to_rgba`, `capture_window_context`), manajemen multi-monitor (`PillSize`, `SYNC_DISPLAYS_QUEUE`), `setup` handler, tray menu, panic hook, serta unit test di modul `hit_test`.
2. `src-tauri/tauri.conf.json` (baris 1-83): konfigurasi jendela utama, `additionalBrowserArgs`, `security.assetProtocol`, `security.csp`, bundle, dan updater.
3. `src-tauri/capabilities/default.json` (baris 1-54): daftar target window dan seluruh izin plugin/core.
4. Skrip verifikasi mandiri Node: `tests/bug-hunt/T01_config_and_utf8_check.mjs` (verifikasi konfigurasi JSON, konsistensi `WEBVIEW_BROWSER_ARGS`, keunikan `invoke_handler`, serta layout byte UTF-8 literal `" • "`).

### Tidak Sempat / Tidak Dapat Diperiksa Langsung
- Eksekusi `cargo test` / `cargo check` / `cargo build` serta pengujian runtime langsung pada aplikasi desktop Windows asli tidak dilakukan sesuai aturan pembatasan tugas, sehingga perilaku runtime Rust dikategorikan sebagai `DUGAAN DARI KODE [BELUM DIVERIFIKASI DI DESKTOP ASLI]`.

## 3. Rincian Temuan

### T01-01
- **ID**: `T01-01`
- **Judul**: Panic UTF-8 non-char-boundary pada pemisahan `" • "` di thread polling SMTC mematikan thread & memicu panic hook
- **Lokasi**: `src-tauri/src/lib.rs:5900-5902` (berdampak ke `src-tauri/src/lib.rs:4491-4496`)
- **Kategori**: Integrasi Windows
- **Keparahan**: `TINGGI`
- **Frekuensi**: `Kondisional`
- **Status Verifikasi**: `DUGAAN DARI KODE` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Putar media pada pemutar desktop non-browser atau browser yang tidak termasuk daftar pengecualian di baris 5806-5811 (mis. Opera, Vivaldi, Zen, Arc, atau judul dengan lebih dari satu `" • "`) dengan `artist` kosong atau generik sehingga eksekusi masuk ke blok `src-tauri/src/lib.rs:5840`.
  2. Pastikan `title` mengandung pemisah `" • "` dan tidak mengandung `" - "` maupun `" | "`, misalnya `"Judul Lagu • Nama Artis"`.
  3. Tunggu siklus polling SMTC (setiap 500 ms) mencapai `src-tauri/src/lib.rs:5900-5902`.
- **Hasil Sebenarnya**:
  Karakter `'•'` (`U+2022`) berukuran 3 byte dalam UTF-8 (`0xE2 0x80 0xA2`), sehingga literal `" • "` berpanjang total 5 byte (`0x20 0xE2 0x80 0xA2 0x20`). Mengiris `title[idx + 3..]` mengarahkan indeks tepat ke byte ke-3 (`0xA2`) di tengah karakter `'•'`, yang bukan batas karakter UTF-8. Rust langsung mengalami panic (`byte index ... is not a char boundary; it is inside '•'`). Panic tersebut:
  1) Memicu panic hook global (`src-tauri/src/lib.rs:4492-4496`) yang memanggil `taskbar_manager::restore_taskbar_on_exit()` dan `window_preview::cleanup_window_previews()` padahal aplikasi masih berjalan.
  2) Mematikan thread polling utama (baris 5290-6167) secara permanen sehingga pemantauan SMTC, notifikasi toast, clipboard, Caps Lock, volume, baterai, USB, dan pergantian perangkat audio berhenti total sampai aplikasi dimulai ulang.
- **Hasil yang Diharapkan**:
  Pemisahan `" • "` menggunakan `idx + " • ".len()` (`idx + 5`) atau `title.rsplit_once(" • ")` tanpa pernah memotong di tengah karakter UTF-8.
- **Bukti**:
  Cuplikan `src-tauri/src/lib.rs:5900-5902`:
  ```rust
  } else if let Some(idx) = title.rfind(" • ") {
      artist = title[idx + 3..].trim().to_string();
      title = title[..idx].trim().to_string();
  ```
  Cuplikan `src-tauri/src/lib.rs:4492-4496`:
  ```rust
  std::panic::set_hook(Box::new(move |panic_info| {
      taskbar_manager::restore_taskbar_on_exit();
  window_preview::cleanup_window_previews();
      default_panic_hook(panic_info);
  }));
  ```
  Output `node tests/bug-hunt/T01_config_and_utf8_check.mjs`:
  ```
  [CHECK] UTF-8 bytes dari ' • ': 0x20 0xE2 0x80 0xA2 0x20
  [CHECK] Panjang byte ' • ': 5 | byte di offset +3: 0xA2 | continuation byte: true
  ```
- **Dugaan Akar Masalah**:
  Asumsi panjang literal `" • "` disamakan dengan `" - "` dan `" | "` (3 byte ASCII) pada dua cabang di atasnya (`src-tauri/src/lib.rs:5894-5899`), padahal `'•'` bernilai 3 byte UTF-8.
- **Usulan Perbaikan**:
  Ganti `rfind` + indexing manual pada baris 5894-5903 dengan `title.rsplit_once(" • ")` (serta `rsplit_once(" - ")` dan `rsplit_once(" | ")`).
- **Risiko Perbaikan**:
  Sangat rendah; `rsplit_once` merupakan operasi aman tanpa panic untuk semua input UTF-8.

### T01-02
- **ID**: `T01-02`
- **Judul**: Potensi self-deadlock `PillSize` Mutex pada `update_pill_size` saat memanggil `position_notch_window`
- **Lokasi**: `src-tauri/src/lib.rs:2307-2328` (berinteraksi dengan `src-tauri/src/lib.rs:1900-1911` dan `src-tauri/src/lib.rs:4830-4864`)
- **Kategori**: Konkurensi/Race Condition
- **Keparahan**: `TINGGI`
- **Frekuensi**: `Kondisional`
- **Status Verifikasi**: `DUGAAN DARI KODE` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Panggil command sinkron `update_pill_size` dengan perubahan `top_offset`, `is_island`, `is_bottom`, atau `position` sehingga `should_reposition == true` (`src-tauri/src/lib.rs:2308-2311`).
  2. Saat bersamaan, ukuran fisik jendela aktual berbeda dari `(820.0 * m_sf, 460.0 * m_sf)` (mis. baru berpindah DPI atau ukuran awal jendela belum sinkron).
  3. `update_pill_size` masih memegang `state.0.lock()` ketika `position_notch_window` memanggil `window.set_position(...)` dan `window.set_size(...)` (`src-tauri/src/lib.rs:1908-1910`).

- **Hasil yang Diharapkan**:

  `MutexGuard` pada `update_pill_size` tidak dibatasi scopenya hanya untuk pembaruan state `PillState`, melainkan ikut dipertahankan saat pemanggilan operasi Win32/Tauri windowing.
- **Usulan Perbaikan**:
  Salin nilai `(should_reposition, dpr, target_monitor)` di dalam scope lock singkat, tutup blok lock, lalu panggil `window.scale_factor()` dan `position_notch_window(...)` di luar lock.

### T01-03
- **ID**: `T01-03`
- **Judul**: Cacat lifecycle `ACTIVE_AI_STREAMS`: tabrakan `stream_id`, cancel tidak memutus koneksi blocking, dan stream tanpa batas ukuran
- **Lokasi**: `src-tauri/src/lib.rs:1120-1247`
- **Kategori**: Memori/Resource
- **Keparahan**: `TINGGI`
- **Frekuensi**: `Kondisional`
- **Status Verifikasi**: `DUGAAN DARI KODE` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Jalankan `ai_http_stream` dengan `stream_id = "s1"` ke server yang lambat atau tidak menutup koneksi.
  2. Kasus tabrakan ID: sebelum stream pertama selesai, panggil `ai_http_stream` lagi dengan `stream_id = "s1"`, lalu akhiri stream pertama dan panggil `cancel_ai_http_stream("s1")`.
  3. Kasus pembatalan I/O macet: panggil `cancel_ai_http_stream("s1")` saat thread `spawn_blocking` sedang menunggu di `request.send_string`/`request.call()` atau `reader.lines()`.
  4. Kasus payload tanpa newline: kirim respons HTTP berukuran sangat besar tanpa `\n` ke `ai_http_stream`.
- **Hasil Sebenarnya**:
  1. `map.insert(stream_id.clone(), Arc::clone(&cancel_flag))` (`lib.rs:1166`) menimpa flag milik stream lama sehingga stream lama tidak dapat dibatalkan. Saat stream lama keluar, `AiStreamRegistryGuard::drop` (`lib.rs:1135`) menjalankan `map.remove(&self.0)` tanpa membandingkan pointer `Arc`, sehingga menghapus entri milik stream kedua yang masih berjalan dan membuatnya ikut tidak dapat dibatalkan.
  2. `cancel_ai_http_stream` hanya menyetel `AtomicBool` (`lib.rs:1144`) dan tidak menutup socket/transport. Thread `spawn_blocking` dan koneksi TCP tetap tersangkut di `send_string`/`call` atau `reader.lines()` hingga server mengirim data atau timeout 120 detik (`lib.rs:1180`) tercapai.
  3. `BufReader::new(resp.into_reader()).lines()` (`lib.rs:1211-1212`) membaca tanpa batas byte per baris maupun batas total respons, sehingga satu baris panjang tanpa `\n` dapat memicu alokasi memori tak terbatas hingga OOM.
- **Hasil yang Diharapkan**:
  Entri `ACTIVE_AI_STREAMS` dilindungi dari penimpaan ID duplikat dan `Drop` hanya menghapus jika pointer `Arc` cocok (`Arc::ptr_eq`); pembatalan memutus I/O atau memakai HTTP client non-blocking yang dapat di-abort (`tokio`/cancellation token); pembacaan stream menerapkan batas maksimum ukuran baris dan total byte.
- **Bukti**:
  Cuplikan `src-tauri/src/lib.rs:1130-1138, 1141-1148, 1164-1167, 1210-1215`:
  ```rust
  impl Drop for AiStreamRegistryGuard {
      fn drop(&mut self) {
          if let Ok(mut map) = active_ai_streams().lock() {
              map.remove(&self.0);
          }
      }
  }
  ...
  if let Ok(mut map) = active_ai_streams().lock() {
      map.insert(stream_id.clone(), Arc::clone(&cancel_flag));
  }
  ...
  let reader = std::io::BufReader::new(resp.into_reader());
  for line in reader.lines() {
      if flag_clone.load(Ordering::SeqCst) {
          return;
      }
  ```
- **Dugaan Akar Masalah**:
  Manajemen stream berbasis `HashMap<String, Arc<AtomicBool>>` dan blocking I/O `ureq` tidak mendukung pembatalan socket secara aktif, tidak memverifikasi kepemilikan entri saat `Drop`, serta tidak membatasi reader.
- **Usulan Perbaikan**:
  1) Tolak `stream_id` duplikat atau batalkan flag lama sebelum menyisipkan yang baru, dan simpan `Arc<AtomicBool>` di `AiStreamRegistryGuard` agar `Drop` hanya memanggil `remove` jika `map.get(&id).is_some_and(|cur| Arc::ptr_eq(cur, &self.flag))`.
  2) Gunakan `take(MAX_LINE_BYTES)` / pembacaan berbatas untuk mencegah baris tak terbatas, serta pertimbangkan `reqwest` async + `tokio::select!` dengan cancellation token agar socket langsung terputus saat `cancel_ai_http_stream` dipanggil.
- **Risiko Perbaikan**:
  Sedang bila bermigrasi dari `ureq` ke HTTP client async; sangat rendah untuk perbaikan `AiStreamRegistryGuard` dan pembatas baca `BufRead`.
