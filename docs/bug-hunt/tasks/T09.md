## 3. Rincian Temuan

### T09-01
- **ID**: `T09-01`
- **Judul**: `saveNavbarConfig` mengembalikan Promise sebelum `settings.json` disimpan (debounce 250ms tanpa flush) sehingga aktivasi/reset Taskbar batal saat jendela cepat dimuat atau ditutup
- **Lokasi**: `src/services/navbarConfigService.ts:469-519` (berkaitan dengan `src/services/navbarConfigService.ts:394-467`, `src/components/settingsWindow/navbar/NavbarSettingsTab.tsx:143,151,271-286`, dan `src/components/navbar/NavbarApp.tsx:69-73,163-176`)
- **Kategori**: Konkurensi/Race Condition
- **Keparahan**: `TINGGI`
- **Frekuensi**: `Sering`
- **Status Verifikasi**: `TERBUKTI LEWAT UJI` (`tests/bug-hunt/T09-verify.mjs`, `TEST-1A`) `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Simpan konfigurasi awal di `settings.json` dengan `opt_navbar_config.enabled = false`.
  2. Di `NavbarSettingsTab`, aktifkan Taskbar (`handlePatch({ enabled: true })`) atau klik `Yes, Reset` (`handleReset()`), yang memanggil `await saveNavbarConfig(...)`.
  3. Langsung setelah `await saveNavbarConfig(...)` selesai (< 250ms), `NavbarSettingsTab` memanggil `invoke("toggle_navbar", { enabled: true })` (membuat WebView `navbar` yang memanggil `loadNavbarConfig()`), atau pengguna langsung menutup jendela Pengaturan (`win.destroy()`).
- **Hasil Sebenarnya**: `saveNavbarConfig` langsung resolve pada 0ms sementara penulisan ke `settings.json` ditunda di `setTimeout(..., 250)` tanpa `flush` saat `beforeunload` dan tanpa ditunggu oleh `Promise`. `loadNavbarConfig()` di jendela `navbar` (atau pada peluncuran berikutnya) menemukan `store.get("opt_navbar_config")` masih berisi `enabled: false`, melewatkan fallback `localStorage`, lalu menimpa `localStorage` kembali ke `enabled: false`. Di `NavbarApp.tsx:69-72`, ini bahkan dapat memicu `close_navbar_window` dan mengembalikan taskbar Windows.
- **Hasil yang Diharapkan**: Setelah `await saveNavbarConfig(...)` selesai (atau sebelum jendela ditutup / `toggle_navbar` dipanggil), `settings.json` sudah konsisten atau `loadNavbarConfig` tidak menimpa perubahan terbaru yang belum sempat di-flush, dan ada flush paksa saat `beforeunload`/`pagehide`.
- **Bukti**:
  Cuplikan `src/services/navbarConfigService.ts:508-518`:
  ```ts
  // 6. Debounced disk persistence to store (never blocks UI or IPC thread)
  pendingConfigToSave = normalized;
  if (debouncedSaveTimer) clearTimeout(debouncedSaveTimer);
  debouncedSaveTimer = setTimeout(() => {
    if (pendingConfigToSave) {
      flushConfigToStore(pendingConfigToSave);
      pendingConfigToSave = null;
    }
  }, 250);

  return normalized;
  ```
  Cuplikan `src/services/navbarConfigService.ts:403,418,458`:
  ```ts
  loadedData = await store.get<unknown>(STORE_KEY);
  ...
  if (!loadedData && typeof window !== "undefined") { ... }
  ...
  localStorage.setItem(LOCAL_STORAGE_KEY, JSON.stringify(normalized));
  ```
  Output `node tests/bug-hunt/T09-verify.mjs`:
  ```text
  [PASS] TEST-1A saveNavbarConfig unawaited 250ms debounce reverts enabled=true: storeAfterAwait.enabled=false, loadNavbarConfig().enabled=false, localStorageAfterLoad.enabled=false
  ```
- **Dugaan Akar Masalah**: `saveNavbarConfig` menunda `flushConfigToStore` di dalam `setTimeout(250)` namun tetap bertipe `async` yang langsung mengembalikan nilai tanpa mekanisme flush sinkron/event penutupan jendela, sementara `loadNavbarConfig` memprioritaskan `settings.json` secara mutlak ketika key ada.
- **Usulan Perbaikan**: Sediakan opsi `{ immediate?: boolean }` pada `saveNavbarConfig` (wajib `immediate: true` untuk `enabled`, `hideWindowsTaskbar`, `handleReset`, dan sebelum `toggle_navbar`), tambahkan listener `pagehide`/`beforeunload` untuk mem-flush `pendingConfigToSave`, dan jadwalkan `store.set` segera (hanya mendebounce `store.save()` atau menyimpan timestamp revisi).
- **Risiko Perbaikan**: Menulis `store.set` tanpa debounce saat drag slider dapat meningkatkan IPC ke `plugin-store`; pisahkan immediate save untuk aksi diskrit dan debounce + flush-on-unload khusus slider.

### T09-03
- **ID**: `T09-03`
- **Judul**: `shortcutManager.applyAll` diam-diam meng-unregister dan mencuri handler jika ada dua aksi memakai pintasan sama

- **Keparahan**: `TINGGI`

- **Langkah Reproduksi**:
  1. Berikan peta pintasan yang memiliki duplikat ke `shortcutManager.applyAll` (misal pengguna versi lama pernah mengatur `quick_task` ke `"Control+Alt+A"`, lalu pembaruan menambahkan `open_ai_chat` dengan default `"Control+Alt+A"` lewat merge `{ ...DEFAULT_SHORTCUTS, ...savedMap }`, atau `settings.json` / `localStorage` termodifikasi).
  2. Panggil `shortcutManager.applyAll(map, true, handlers)`.
- **Hasil Sebenarnya**: Pada iterasi pertama (`quick_task`), `applyAllInternal` mendaftarkan `"Control+Alt+A"` dan menandai `statusMap.quick_task = "ok"`. Pada iterasi berikutnya (`open_ai_chat`), baris 406 menjalankan `await unregister("Control+Alt+A")` yang **menghapus pendaftaran OS milik `quick_task`**, lalu mendaftarkan callback `open_ai_chat` dan menandai `statusMap.open_ai_chat = "ok"`. Akibatnya `quick_task` mati total namun UI menampilkan kedua aksi berstatus `"ok"` (tanpa ikon konflik).
- **Hasil yang Diharapkan**: `applyAllInternal` mendeteksi duplikasi accelerator di dalam `map` sebelum mendaftarkan ke OS, menjaga registrasi pertama tetap aktif, dan menandai entri duplikat dengan status `"conflict"`.
- **Bukti**:
  Cuplikan `src/services/shortcuts.ts:403-418`:
  ```ts
  try {
    // Clean up any existing registration in Windows OS first to avoid self-collision

      await unregister(shortcut);

  ```
  Output `node tests/bug-hunt/T09-verify.mjs`:

- **Dugaan Akar Masalah**: `applyAllInternal` memanggil `unregister(shortcut)` secara membabi buta di dalam loop tanpa melacak `Set<string>` accelerator yang sudah didaftarkan pada iterasi sebelumnya.
- **Usulan Perbaikan**: Pertahankan `seenNormalized = new Set<string>()` di dalam `applyAllInternal`; jika `seenNormalized.has(shortcut.toLowerCase())`, langsung set `statusMap[action.id] = "conflict"` dan `continue` tanpa memanggil `unregister(shortcut)`.
- **Risiko Perbaikan**: Rendah; memastikan konflik internal tampil jelas di UI agar pengguna bisa mengganti salah satu pintasan.

## 4. Tidak Ditemukan Cacat

Berikut area yang telah diperiksa secara langsung dan tidak ditemukan cacat berarti pada pemeriksaan ini:
1. **Keamanan pembuatan shortcut di `src-tauri/src/migration.rs:91-107`**: Pembuatan shortcut melalui PowerShell menggunakan environment variable (`GILI_LNK_PATH`, `GILI_TARGET_EXE`) alih-alih interpolasi string perintah, sehingga aman dari injeksi token path; fungsi perencanaan jalur (`legacy_notch_dir`, `plan_stale_shortcut_removals`, `remove_existing_files`) juga disertai unit test memadai di baris 193-275.
2. **Keutuhan kunci terjemahan `i18n.ts` pada seluruh UI pengaturan T09**: Audit statis via `TEST-6` di `tests/bug-hunt/T09-verify.mjs` memverifikasi bahwa seluruh panggilan `t("...")` dan `tr("...")` pada 22 berkas UI lingkup T09 memiliki entri yang valid di `translations` (`missingKeys=[]`).
3. **Fallback & normalisasi struktural `tabConfigService.ts:64-147`**: `loadTabsPreferences` dan `normalizeTabsPreferences` aman terhadap `localStorage` kosong, JSON rusak, duplikasi ID tab, maupun skenario semua tab dimatikan (selalu menjamin minimal satu tab inti tetap aktif).
4. **Lisensi Taskbar Pro & Isolasi `crossWindowSync.ts`**: `taskbarProService.ts` menangani kegagalan invoke dengan fallback aman dan sinkronisasi lintas jendela idempoten; `crossWindowSync.ts` memiliki `WINDOW_ORIGIN_ID` untuk mencegah loop event lokal.
5. **Tampilan statis/navigasi `SettingsSidebar.tsx`, `AboutView.tsx`, `SupportView.tsx`, `IdleTab.tsx`, `NotchPositionPreviewSelector.tsx`, `TransparencyControlSection.tsx`, `WindowsBannerRow.tsx`, `NavbarPositionCard.tsx`, `NavbarIconThemeCard.tsx`, `NavbarLivePreview.tsx`, `AddModuleDialog.tsx`, `SettingsSubnav.tsx`, `SettingsPanel.tsx`**: Struktur state, kontrol, dan pemetaan opsi sudah konsisten dengan kontrak props-nya (catatan kecil yang sifatnya non-blocking atau di luar fokus utama tidak dinaikkan sebagai bug palsu: mis. teks `"Aktif"` yang belum terlokalisasi di `MonitorSelector.tsx:142`, hilangnya opsi `isLightMode` di `NotifSoundPicker.tsx`, serta reset `copiedTarget` timer di `SupportView.tsx:43` bila dua tombol salin diklik dalam < 2 detik).
