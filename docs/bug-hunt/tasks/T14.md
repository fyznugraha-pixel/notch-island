- **ID**: `T14-01`
- **Judul**: Seluruh 6 path aset logo MSIX di `AppxManifest.xml` tidak ada di repositori (`Assets\GILI-*`) dan `MaxVersionTested` tertahan di 10.0.22000.1
- **Lokasi**: `AppxManifest.xml:9,18,25-26`
- **Kategori**: Build/Versi
- **Keparahan**: `TINGGI`
- **Frekuensi**: `Selalu`
- **Status Verifikasi**: `TERBUKTI LEWAT UJI` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Baca referensi aset visual pada `AppxManifest.xml` baris 9, 25, dan 26.
  2. Periksa keberadaan direktori `Assets/` di root repositori serta daftar berkas di `src-tauri/icons/` menggunakan `node tests/bug-hunt/T14_verify.mjs`.
  3. Coba jalankan `makeappx.exe pack /d . /p Gili.msix` menggunakan `AppxManifest.xml` di root repositori.
- **Hasil Sebenarnya**:
  1) Direktori `Assets/` tidak ada di root repositori (`rootExists=false` untuk keenam aset).
  2) Di dalam `src-tauri/icons/`, berkas yang ada bernama `StoreLogo.png`, `Square150x150Logo.png`, `Square44x44Logo.png`, `Square310x310Logo.png`, dan `Square71x71Logo.png` tanpa prefiks `GILI-`, sedangkan `Wide310x150Logo.png` (maupun `GILI-Wide310x150Logo.png`) sama sekali tidak ada di repositori.

- **Hasil yang Diharapkan**:
  Seluruh path aset di `AppxManifest.xml` merujuk ke berkas gambar yang benar-benar ada di repositori (atau skrip pemaket MSIX menyalin dan menamai ulang aset termasuk `Wide310x150Logo.png` secara otomatis), dan `MaxVersionTested` diperbarui ke build Windows 11 terkini yang diuji.

  `AppxManifest.xml` dihasilkan oleh MSIX Packaging Tool (`<!--Package created by MSIX Packaging Tool version: 1.2024.405.0-->` pada baris 3) dari lingkungan lokal pembuat tanpa menyertakan folder `Assets\` hasil ekstraksi MSIX ke dalam repositori Git.

### T14-03
- **ID**: `T14-03`
- **Judul**: Ketiadaan `@media (prefers-reduced-motion: reduce)` di seluruh CSS, ketiadaan `<MotionConfig reducedMotion="user">`, dan tiadanya fallback `addListener` di `usePrefersReducedMotion.ts`
- **Lokasi**: `src/index.css:24-44`, `src/App.css:1-349`, `src/styles/taskbarTheme.css:330-355`, `src/hooks/usePrefersReducedMotion.ts:9-16`, `src/utils/iosMotion.ts:5-49`
- **Kategori**: Aksesibilitas
- **Keparahan**: `SEDANG`
- **Frekuensi**: `Selalu`
- **Status Verifikasi**: `TERBUKTI LEWAT UJI` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Aktifkan pengaturan Windows "Animation effects: Off" (`prefers-reduced-motion: reduce`).
  2. Periksa berkas CSS (`src/index.css`, `src/App.css`, `src/styles/taskbarTheme.css`) dan kode komponen (`Tooltip.tsx`, `IosSwitch.tsx`, `IosSegmentedControl.tsx`, `IosTile.tsx`, `NavbarPopoverShell.tsx`).
  3. Jalankan `node tests/bug-hunt/T14_verify.mjs` untuk memverifikasi keberadaan aturan `@media (prefers-reduced-motion: reduce)`, `<MotionConfig>`, dan fallback `addListener`.
- **Hasil Sebenarnya**:
  1) Tidak ada satu pun aturan `@media (prefers-reduced-motion: reduce)` di `src/index.css`, `src/App.css`, maupun `src/styles/taskbarTheme.css`. Animasi CSS tanpa henti seperti `.animate-marquee` (`index.css:28-30`), `.animate-eq-bar` (`index.css:40-44`), dan `.animate-pulse` tetap berjalan terus-menerus.
  2) Meskipun hook `usePrefersReducedMotion` (`src/hooks/usePrefersReducedMotion.ts:3`) tersedia, aplikasi tidak membungkus pohon React dengan `<MotionConfig reducedMotion="user">` dari `framer-motion`, dan komponen `Tooltip.tsx`, `IosSegmentedControl.tsx`, `IosSwitch.tsx`, `IosTile.tsx`, `IosSlider.tsx`, serta `NavbarPopoverShell.tsx` (termasuk animasi Genie 3D di baris 343-429) tetap menjalankan animasi spring/scale/rotasi penuh.
  3) `usePrefersReducedMotion.ts:14-15` memanggil `mq.addEventListener("change", handleChange)` secara langsung tanpa pengecekan `typeof mq.addEventListener === "function"` (fallback `mq.addListener` untuk runtime WebView/browser lama).
- **Hasil yang Diharapkan**:
  1) CSS menyertakan `@media (prefers-reduced-motion: reduce)` untuk menghentikan animasi dekoratif berulang (`animation: none !important; transition-duration: 0.01ms !important`).
  2) Akar aplikasi (`App`, `NavbarApp`, `SettingsWindowApp`, `TaskbarFlyoutApp`, `MiniPlayerApp`, `LyricsShareWindowApp`) dibungkus `<MotionConfig reducedMotion="user">` atau menghormati `usePrefersReducedMotion()`.
  3) `usePrefersReducedMotion.ts` memiliki fallback `addListener`/`removeListener`.
- **Bukti**:
  Cuplikan `src/hooks/usePrefersReducedMotion.ts:9-16`:
  ```ts
    useEffect(() => {
      if (typeof window === "undefined" || !window.matchMedia) return;
      const mq = window.matchMedia("(prefers-reduced-motion: reduce)");
      setReduced(mq.matches);
      const handleChange = (e: MediaQueryListEvent) => setReduced(e.matches);
      mq.addEventListener("change", handleChange);
      return () => mq.removeEventListener("change", handleChange);
    }, []);
  ```
  Keluaran `node tests/bug-hunt/T14_verify.mjs`:
  ```text
  prefers-reduced-motion in index.css: false
  prefers-reduced-motion in App.css: false
  prefers-reduced-motion in taskbarTheme.css: false
  <MotionConfig usage in src: []
  Test B (legacy MediaQueryList without addEventListener): throws TypeError = true
  ```
- **Dugaan Akar Masalah**:
  `usePrefersReducedMotion` hanya dipasang secara manual pada sebagian kecil komponen, sedangkan lapisan CSS global dan konfigurasi global Framer Motion belum ditambahkan.
- **Usulan Perbaikan**:
  Tambahkan blok `@media (prefers-reduced-motion: reduce)` di `src/index.css` dan `src/App.css`, bungkus root window dengan `<MotionConfig reducedMotion="user">`, serta tambahkan fallback `if (mq.addEventListener) ... else mq.addListener(...)` di `usePrefersReducedMotion.ts`.
- **Risiko Perbaikan**:
   sangat rendah; hanya memengaruhi pengguna yang secara eksplisit mengaktifkan pengurangan gerakan di tingkat OS.

### T14-09
- **ID**: `T14-09`
- **Judul**: Plugin Vite `slim-icon-barrels` memindai `src/` hanya sekali saat startup server dan tidak memiliki `manualChunks` maupun `@types/node`
- **Lokasi**: `vite.config.ts:3-8,12-85`, `package.json:37-47`
- **Kategori**: Build/Versi
- **Keparahan**: `RENDAH`
- **Frekuensi**: `Kondisional`
- **Status Verifikasi**: `TERBUKTI LEWAT UJI` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Baca `vite.config.ts` baris 3-8 dan 48-85.
  2. Perhatikan kapan `usedLucideIcons` dan `usedSimpleIcons` dihitung (`vite.config.ts:49-50`).
  3. Selama `npm run dev` berjalan, tambahkan impor ikon baru dari `lucide-react` pada salah satu komponen di `src/` tanpa me-restart server Vite.
- **Hasil Sebenarnya**:
  1) `usedLucideIcons` dan `usedSimpleIcons` dihitung satu kali di level top-level modul (`vite.config.ts:48-50`) ketika `vite.config.ts` pertama kali dievaluasi. Saat pengembang menambahkan ikon baru dari `lucide-react` atau `@icons-pack/react-simple-icons` di tengah sesi `vite dev`, barrel yang telah difilter tidak memuat ekspor ikon baru tersebut sampai server Vite di-restart.
  2) `filterBarrelSource` (`vite.config.ts:52-65`) mengasumsikan setiap baris ekspor diawali `export {` dan memiliki spasi sebelum nama simbol (`line.includes(\` ${sym},\`) || line.includes(\` ${sym} \`)`). Jika pembaruan minor `lucide-react` atau `@icons-pack/react-simple-icons` memformat ulang berkas `.mjs` menjadi multi-baris atau tanpa spasi (`export{Icon}`), filter akan menghasilkan barrel kosong dan fallback ke seluruh barrel penuh.
  3) `vite.config.ts:3-8` menggunakan tiga komentar `// @ts-expect-error type error without @types/node package` karena `@types/node` tidak tercantum di `devDependencies` `package.json`.
- **Hasil yang Diharapkan**:
  Plugin `slim-icon-barrels` hanya diaktifkan pada mode build (`apply: "build"`) atau menyegarkan daftar simbol saat file berubah di mode dev, serta `@types/node` ditambahkan ke `devDependencies`.

  Cuplikan `vite.config.ts:48-50,70-85`:
  ```ts
  const srcDir = path.resolve(process.cwd(), "src");
  const usedLucideIcons = collectImportedSymbols(srcDir, "lucide-react");

  ```
- **Dugaan Akar Masalah**:
  Optimasi barrel ikon dibuat untuk mempercepat pemuatan modul tanpa memisahkan perilaku antara `vite dev` (HMR dinamis) dan `vite build` (statis).
- **Usulan Perbaikan**:
  Hitung ulang `collectImportedSymbols` di dalam hook `load()` saat mode dev (atau batasi `slim-icon-barrels` dengan `optimizeDeps` Vite), dan tambahkan `@types/node` pada `devDependencies`.
- **Risiko Perbaikan**:
  Sangat rendah; hanya memengaruhi alur kerja pengembangan (`vite dev`).
