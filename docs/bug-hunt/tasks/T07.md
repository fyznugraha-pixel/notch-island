### T07-02
- **ID**: `T07-02`
- **Judul**: Ketidakcocokan tipe payload event `master-volume-changed` membuat volume utama di Mixer dan Output Audio tidak tersinkronisasi
- **Lokasi**: `src/modules/components/MixerNavbarModule.tsx:67-73, 296-302`
- **Kategori**: Integrasi Windows
- **Keparahan**: `TINGGI`
- **Frekuensi**: `Selalu`
- **Status Verifikasi**: `TERBUKTI LEWAT UJI` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Pasang modul `Mixer suara` (`MixerNavbarModule`) atau `Output audio` (`AudioOutputNavbarModule`) di taskbar.
  2. Ubah volume utama Windows lewat tombol volume keyboard, System Tray Windows, atau aplikasi lain.
  3. Backend Rust memancarkan event `"master-volume-changed"` dengan payload `{ volume, muted }`.
- **Hasil Sebenarnya**:
  - Kedua listener mengharapkan `listen<number>("master-volume-changed", ...)` dan menguji `if (typeof ev.payload === "number")`.
  - Karena payload dari Rust berbentuk objek `{ volume: f32, muted: bool }` (`src-tauri/src/lib.rs:5397-5405`), kondisi `typeof ev.payload === "number"` selalu bernilai `false`. Nilai `masterVol` di kedua modul tidak pernah diperbarui dari event tersebut.
- **Hasil yang Diharapkan**:
  - Kedua listener membaca `ev.payload?.volume` (sekaligus mendukung fallback `number` jika suatu saat dipancarkan angka) dan memperbarui `masterVol` secara langsung.
- **Bukti**:
  `src/modules/components/MixerNavbarModule.tsx:67-73` (pola identik pada baris `296-302`):
  ```tsx
      const unlisten = listen<number>("master-volume-changed", (ev) => {
        if (typeof ev.payload === "number") {
          setMasterVol(
            ev.payload <= 1 ? Math.round(ev.payload * 100) : Math.round(ev.payload)
          );
        }
      });
  ```
  `src-tauri/src/lib.rs:5397-5405`:
  ```rust
      struct VolumeUpdatePayload {
          volume: f32,
          muted: bool,
      }
      let _ = app_handle.emit("master-volume-changed", VolumeUpdatePayload {
          volume: level,
          muted: cur_mute,
      });
  ```
  Output `node tests/bug-hunt/T07-verify.mjs`:
  ```
  [Test 4] master-volume-changed payload mismatch...
    PROVED: Rust emits {"volume":0.85,"muted":false}; listener checks typeof ev.payload === "number" -> stays stale at 50%.
  ```
- **Dugaan Akar Masalah**: Perubahan kontrak payload event `"master-volume-changed"` di backend Rust menjadi struct `{ volume, muted }` tidak diikuti pembaruan tipe dan pembacaan payload di `MixerNavbarModule.tsx`.
- **Usulan Perbaikan**: Terima payload `{ volume?: number; muted?: boolean } | number` di kedua listener `MixerNavbarModule` dan `AudioOutputNavbarModule`, ekstrak nilai numeriknya, lalu tampilkan status bisu/0% secara konsisten ketika `muted === true`.
- **Risiko Perbaikan**: Sangat rendah.

### T07-04
- **ID**: `T07-04`
- **Judul**: Stale closure pada interval 30 menit menimpa ulang kota pilihan pengguna pada modul Cuaca dan Kualitas Udara
- **Lokasi**: `src/modules/components/WeatherNavbarModule.tsx:80-87` dan `src/modules/components/MediaLifestyleExtraModules.tsx:205-209`

- **Keparahan**: `TINGGI`
- **Frekuensi**: `Selalu`
- **Status Verifikasi**: `TERBUKTI LEWAT UJI` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Pasang modul `Cuaca` (`WeatherNavbarModule`) atau `Kualitas udara` (`AirQualityNavbarModule`) dengan cache awal kosong atau kota `"Bandung"`.
  2. Buka popover lalu ubah kota ke `"Tokyo"` atau `"Jakarta"`.

- **Hasil yang Diharapkan**:
  - Interval polling 30 menit selalu membaca kota aktif terkini (misalnya lewat `useRef` yang diperbarui tiap kota berubah atau efek yang bergantung pada kota terpilih).

  ```tsx
    useEffect(() => {
  ```

  `src/modules/components/MediaLifestyleExtraModules.tsx:205-209`:
  ```tsx
    useEffect(() => {
  ```

### T07-05
- **ID**: `T07-05`
- **Judul**: Race condition fetch asinkron, ketiadaan timeout/abort, dan error `localStorage.setItem` palsu pada Cuaca & AQI
- **Lokasi**: `src/services/ambientEnvironmentService.ts:47-146`, `src/modules/components/WeatherNavbarModule.tsx:59-78`, `src/modules/components/MediaLifestyleExtraModules.tsx:178-203`
- **Kategori**: Konkurensi/Race Condition
- **Keparahan**: `SEDANG`
- **Frekuensi**: `Kondisional`
- **Status Verifikasi**: `TERBUKTI LEWAT UJI` `[BELUM DIVERIFIKASI DI DESKTOP ASLI]`
- **Langkah Reproduksi**:
  1. Di popover `AirQualityNavbarModule` atau `WeatherNavbarModule`, kirim pencarian kota A lalu segera klik/kirim kota B sebelum respons kota A selesai (atau simulasi respons kota A datang lebih lambat).
  2. Atau uji saat offline/DNS menggantung atau ketika `localStorage.setItem` melempar pengecualian (`QuotaExceededError`).
- **Hasil Sebenarnya**:
  - Tidak ada `AbortController` maupun ID urutan permintaan (`requestIdRef`): respons kota A yang datang belakangan menimpa state dan cache `localStorage` kota B, dan blok `finally { setLoading(false); }` dari permintaan pertama mematikan indikator loading permintaan kedua.
  - `fetch(...)` di `ambientEnvironmentService.ts` tidak menerima `AbortSignal` dan tidak memiliki batas waktu (timeout), sehingga indikator loading dapat berputar lama saat jaringan menggantung.
  - `localStorage.setItem` (`WeatherNavbarModule.tsx:67` dan `MediaLifestyleExtraModules.tsx:186`) tidak dibungkus `try/catch`; jika gagal menulis storage, blok `catch` menampilkan error jaringan palsu padahal data sudah berhasil diambil dan diset ke state.
  - Selain itu di `ambientEnvironmentService.ts:88,91,107-109`, nilai sensor `null` (mis. `us_aqi: null`) dikonversi oleh `Number(null ?? 0)` menjadi `0` (sehingga AQI tidak tersedia tampil seolah `AQI 0 · Baik`).
- **Hasil yang Diharapkan**:
  - Setiap permintaan baru membatalkan atau mengabaikan permintaan sebelumnya, memiliki timeout `fetch` yang wajar, membungkus `localStorage.setItem` dengan `try/catch` terpisah, dan menangani field numerik `null` dari API secara eksplisit.
- **Bukti**:
  `src/modules/components/MediaLifestyleExtraModules.tsx:178-203`:
  ```tsx
    const refreshAqi = async (targetCity: string) => {
      setLoading(true);
      setErrorMsg(null);
      try {
        const live = await fetchLiveAirQuality(targetCity);
        if (live) {
          setAq(live);
          setCityInput(live.city);
          localStorage.setItem(AQI_CACHE_KEY, JSON.stringify(live));
        } else {
  ...
      } finally {
        setLoading(false);
      }
    };
  ```
  Output `node tests/bug-hunt/T07-verify.mjs`:
  ```
    PROVED: Out-of-order async fetch overwrites newer city 'Tokyo' with stale 'Bandung'.
  ```
- **Dugaan Akar Masalah**: Tidak adanya manajemen pembatalan permintaan asinkron dan penanganan batas error lokal vs jaringan pada service serta kedua komponen pemanggilnya.
- **Usulan Perbaikan**: Tambahkan parameter `signal?: AbortSignal` serta timeout (`AbortSignal.timeout`) di `ambientEnvironmentService.ts`, gunakan `requestSeqRef` + `AbortController` per instance modul (termasuk cleanup saat unmount), dan pisahkan `try/catch` untuk `localStorage.setItem`.
- **Risiko Perbaikan**: Rendah.

- **Hasil Sebenarnya**:
  - `PREVIEW_TEXT_EN_REPLACEMENTS` di `moduleI18n.ts:348` mencari `"Mixer 3 aplikasi"`, sedangkan `modules.catalog.json:286` memisahkan tag menjadi `>Mixer</span><span ...>3 aplikasi</span>`, sehingga `"3 aplikasi"` tidak pernah diterjemahkan. Demikian pula `>Layar<` (`tangkap_layar`, baris 207) dan `>hari<` / `UAS Semester` (`hitung_mundur`, baris 318) tetap berbahasa Indonesia.
  - Seluruh 18 komponen modul pada lingkup T07 tidak memeriksa `isPreview` dari `NavbarModuleContext`, sehingga saat jendela Settings terbuka, preview dock tetap menjalankan polling Tauri/WMI/NVML dan fetch jaringan Open-Meteo tambahan.
- **Hasil yang Diharapkan**:
  - `localizePreviewHtml` mencocokkan teks di dalam `<span>` secara tepat untuk semua item katalog, dan modul menghormati `isPreview` bila dirender di dalam `NavbarLivePreview`.
- **Bukti**:
  `src/modules/moduleI18n.ts:348`:
  ```ts

  ```
  `src/modules/modules.catalog.json:286`:
  ```html

  ```
  Output `node tests/bug-hunt/T07-verify.mjs`:

- **Dugaan Akar Masalah**: Daftar string pengganti statis di `moduleI18n.ts` tidak sinkron dengan markup HTML terpisah di `modules.catalog.json`, serta prop `isPreview` belum dimanfaatkan di modul custom.
- **Usulan Perbaikan**: Perbarui entri `PREVIEW_TEXT_EN_REPLACEMENTS` menjadi `">3 aplikasi<"` -> `">3 apps<"`, `">Layar<"` -> `">Screen<"`, `">hari<"` -> `">days<"`, `"UAS Semester"` -> `"Final Exam"`, dan tambahkan guard `if (isPreview) return;` untuk timer/fetch berat saat dibutuhkan.
